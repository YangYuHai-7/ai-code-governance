## 独立 Review

- Reviewer 角色：Builder C 独立交叉 reviewer；覆盖 BA、全栈、架构、安全、测试、多租户治理与 UX 视角。
- 主流程是否可运行：领域对象的测试主流程可运行，但应用/API 主流程不闭环。服务器只实现 `GET /issues`（`server.mjs:5-12`），没有创建、读取单条或状态推进接口；独立 smoke 只能得到授权列表 `200` 和未授权列表 `403`。报告描述的创建和推进只能由开发者直接调用类，终端用户无法完成。
- 测试是否真正覆盖成功 + 两条失败路径：领域层 4/4 通过，覆盖租户内创建/列表、跨租户读取与修改、非成员创建和非法状态迁移。没有 HTTP/API 测试；没有 inactive/suspended membership、伪造身份、角色权限、并发更新、持久化或审计测试。
- 业务不变量与权限边界：issue 的 `tenantId` 固化在创建记录中，读取/修改先按请求 tenant 授权再核对 issue tenant，领域层的基本跨租户隔离有效。但构造器把 membership 仅保存为 role（`issue-tracker.mjs:7-14`），完全丢弃 status。独立探针传入 `status=inactive` 的 member，仍成功创建 issue，直接违反配置中的“only active member”约束。
- 目录、模块和依赖方向：`src/app` 与单一 issues 模块边界简单清楚；身份/membership、issue repository、audit 等独立边界不存在。AICG profile 只检查 placement，dependency direction 与 cohesion 仍为 `stated-only`。
- 安全、可靠性与恢复：HTTP 层直接信任任意客户端提供的 `x-user-id`/`x-tenant-id`（`server.mjs:8`），且内置 demo owner（`server.mjs:4`）。独立 smoke 仅伪造这两个 header 就获得 demo tenant 的 `200`，属于身份验证绕过。所有状态在内存，重启丢失；没有审计、并发版本检查或生产身份来源。因此 tenant 隔离不足以称生产级。
- AICG 生成内容的准确性与噪音：配置和正典正确保存了两条 tenant 约束，`check`/`complete` 均保持 `enforced=unverified`，证据边界准确。但约束未形成 routed business Skill、acceptance case 或 verifier；即使 active membership 未实现、HTTP 可伪造身份、主 API 不完整，`complete --verify 'npm run test'` 仍返回 `ok=true`。对“约束已记录”和“约束已实现”的区分仍不够行动化。
- P0：① 应用/安全——HTTP 身份完全由未认证请求头声明，攻击者可冒充 demo owner 访问 tenant（`server.mjs:4,8`）；② 应用/业务——对外应用仅有列表接口，用户无法完成报告中的创建/读取/推进主流程；③ AICG/治理——已有 tenant/active-member 高风险约束没有被转成必须验证的 acceptance coverage，complete 未暴露上述生产阻断。应用需修复前两项，AICG 需对已确认高风险约束提供验证闭环或强 CTA。
- P1：① 应用/业务/授权——inactive membership 仍被当作 active，独立探针已复现；② 应用/可靠性——issue 与 membership 全为内存状态，无持久化、并发控制和审计；③ AICG/治理——没有 tenant/authorization 专用 profile，未要求 inactive/suspended、伪造身份及跨租户 API 级负向测试。因此当前实现不能称生产级。
- P2：应用/API——所有授权错误统一返回 `403` 并回显内部错误文案（`server.mjs:10-11`），没有稳定错误码，也没有清晰区分未认证、无权限与资源不可见策略。
- 问题归属：API 缺口、header 身份、inactive membership、持久化与审计属于应用；已确认约束没有路由成 Skill/acceptance/negative probes 属于 AICG；`unverified` 没有被冒充为 enforced，是正确的证据边界。
- 建议修复或延期理由：应用必须接入可信认证主体、显式 membership status 与撤权路径，补齐 API 主流程、持久化、审计和 API 级跨租户测试，P0 未解决前不得发布。AICG 应把用户确认的 tenant/active-member 约束转换为可选择的授权验证模板，至少要求 active/inactive/suspended、身份伪造、跨租户读写与撤权回归证据。
