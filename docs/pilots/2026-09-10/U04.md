- 业务不变量与权限边界：顺序执行时三条约束均满足；但每个 `InventoryStore` 在构造时缓存整份文件（`src/modules/inventory/inventory-store.js:5-8`），后续写入基于旧快照整体覆盖（`inventory-store.js:30-32, 47-48`）。独立探针同时创建两个 Store 后依次写入 A、B，重载结果为 `A=null`、仅 B 存在，证明多实例下会静默丢数据并可绕过全局 SKU 唯一性。API 没有认证、授权或审计，任何可达调用方都能改库存。
- 目录、模块和依赖方向：HTTP app 单向依赖 inventory domain/persistence，基本分层清楚；但存储、并发控制和 domain 状态聚合在同一类，文件整体重写使横向扩展不可行。错误状态依赖英文消息正则映射（`src/app/server.js:32-34`），改变文案会改变 HTTP 契约，应改为稳定错误类型/代码。
- 安全、可靠性与恢复：同目录临时文件 + rename 在单进程正常路径上提供原子替换，且成功响应发生在同步持久化之后，这是有效优点。生产风险包括无锁/无版本导致丢写、请求体无限累加（`server.js:12-18`）、无鉴权/限流、JSON 文件损坏时启动直接崩溃（`inventory-store.js:10-13`）、失败临时文件无清理。独立探针还确认同 PID 的遗留 `.tmp` 会令后续写入 `EEXIST`。
