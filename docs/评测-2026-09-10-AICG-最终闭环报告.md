### AICG 历史审计闭环

多轮独立审计曾发现并复现以下高优先级问题，现均有仓库级实现和回归覆盖：

1. X2 可用虚构入口与 exit `0` 绕过 surface 验证；现要求声明入口与运行时 marker 绑定，marker 不匹配会失败。
2. X3 同行 import、无分号连续 import 可漏过 JS/TS module graph；现覆盖同行、多行和 ASI 换行静态语法，并拒绝跨模块私有入口和反向依赖。
3. Brownfield baseline 会把既有债务误当成新增违例；现仅对决策后新增源码执行 new-code-standard。
4. N4 早期仅检查 fixture 字符串、未真实执行风险探针；现六类 vulnerable/repaired fixture 均实际执行，negative/recovery evidence 绑定当前 source/config fingerprint。
5. Legacy context-map seed 迁移曾可能接受冲突 `business_constraints` profile 或错误 manifest authority；现要求窄化的 AICG manifest/schema/generatedBy/tool/template ownership，校验 AGENTS entry ownership/kind/source/current managed hash，并拒绝普通/单双引号及重复同名 profile 冲突，事务失败保持用户内容不变。

## 生产级与证据边界

十个应用的治理结构和项目命令成功，与生产级结论是两条不同的判断链：

- `check/complete exit 0`：证明受管结构、声明入口可达性和一条显式允许的项目命令达到当前契约。
- `productionReadiness=blocked`：说明 owner-confirmed business constraints 或已确认风险仍缺少完整、当前、绑定的业务/负向/恢复 evidence。
- `surface=unverified`：说明检测到的 browser/API/persistence surface 没有真实客户端入口回放。
- `simulation-only`：说明 receipt 是受控 persona 操作记录，不是独立真人、真实客户或真实项目证据。

因此最终可支持的结论仅为：AICG 最终候选在受控 macOS 环境中对十个旧治理副本完成可重复原地升级，并正确阻止证据边界越级。不能支持以下说法：

- 10 位真人用户验证通过；
- 已有真实客户或真实项目采用；
- 已在真实 Codex、Claude Code 或 Cursor 客户端加载；
- 已完成 Windows/Linux 或跨 OS 验证；
- 十个应用已达生产级；
- AICG 或任一 capability pack 已获认证。
