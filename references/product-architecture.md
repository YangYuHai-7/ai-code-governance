# 产品架构：从团队标准到可分发治理产品

本 skill 先服务于团队内部标准化（B），再把经过真实项目验证的部分发布为可分发产品（C）。两者使用同一个治理内核；区别在于证据、兼容性承诺和发布纪律，不是再复制一套模板。

## 产品形态

```text
用户意图
  -> 仓库侦察与拓扑识别
  -> 多轮访谈与决策账本
  -> 能力包选择与证据分级
  -> 治理方案编译
  -> 分阶段落地
  -> 正向门禁 + 负向探针
  -> 真实任务试运行
  -> 反馈进入成长闭环
```

### 治理内核

技术栈无关，负责唯一正典源、上下文路由、规则分层、任务状态、完成门禁、逃生舱、知识记忆、证据台账和成长闭环。内核不得出现 React 组件目录、Spring 注解或 Android Gradle 插件等栈内规则。

### 侦察器

从仓库读取事实，不向用户询问可以测出来的内容：项目拓扑、构建描述文件、语言、框架、包管理器、测试工具、现有 AI 入口、文档、钩子和历史反模式。每个结论带来源路径与置信度。

### 访谈编排器

只询问无法从代码确定的决策：治理深度、支持客户端、强制力、风险偏好、自然语言、候选技术栈、UI 约束、目标 OS、硬边界和完成定义。

### 决策账本

记录已确认选择、仓库事实、默认假设、开放问题、被否决方案和证据等级。它让多轮、跨会话定制可恢复，并阻止后续阶段悄悄改变已经确认的范围。

### 能力包注册表

描述某技术栈如何被识别、需要哪类专家、应该继续问什么、从哪里发现验证命令。能力包给出候选，不直接向目标项目注入通用规则。

### 产物编译器

把确认后的决策编译成目标项目自己的 `AGENTS.md`、`docs/ai/`、适配器、检查器和知识层。生成物只包含被证据支持的内容；未确认项保留为可见 gap。

### 强制与证据层

必须同时保留：

- 正向证据：完整检查通过；
- 负向证据：故意破坏后检查确实失败；
- 使用证据：至少一个真实任务按新框架完成；
- 平台证据：macOS、Windows、Linux 分别记录状态；
- 边界声明：哪些是 `enforced`、`stated`、`unverified`。

跨系统规则见 [cross-platform.md](cross-platform.md)。

## 项目模式

| 模式 | 默认策略 | 禁止的捷径 |
| --- | --- | --- |
| `greenfield` | 先问业务与团队约束，再提出技术栈和 UI 候选 | 先选热门框架再倒推需求 |
| `brownfield` | 保留现有栈，先增量治理 | 把换栈包装成治理必需条件 |
| `monorepo` | 判断共享约定是否足够；否则根路由 + 包级自治 | 根规则覆盖所有包的差异 |
| `repository-family` | 编排仓只管所有权、契约和跨仓记忆 | 在编排仓建立共享实现层 |
| `modernization-assessment` | 独立评估迁移价值、成本和阶段 | 与治理落地在同一范围内执行 |

## 能力证据等级

| 等级 | 含义 | 可以怎么说 |
| --- | --- | --- |
| `certified` | 有固定样例矩阵、负向探针、真实项目试运行和版本记录 | “该组合已通过当前版本认证” |
| `supported` | 有结构化能力包和检查，但真实项目覆盖尚不完整 | “支持该组合，仍有已知验证边界” |
| `unverified` | 通用侦察可处理，但没有专属能力包证据 | “可以定制，尚未认证” |
| `unsupported` | 必需工具、仓库或专家输入缺失 | “当前停止，不猜测实现” |

等级属于**具体能力包版本、组合与操作系统**，不属于语言名称。React 包通过不代表 React + 任意元框架 + 任意 UI 库都通过；macOS 通过也不代表 Windows/Linux 通过。

## B 到 C 的晋级条件

内部团队可以使用 `supported` 能力包，但发布为产品 C 前，每个对外宣称的组合都必须：

1. 在至少两个结构不同的真实项目中试运行；
2. 覆盖新项目与遗留项目中的至少一种，并明确未覆盖哪一种；
3. 通过结构检查、负向探针和真实任务验收；
4. 按声明范围通过 macOS、Windows、Linux 平台矩阵；
5. 记录误判、逃生舱使用和门禁耗时；
6. 由对应栈专家和治理架构师共同签署；
7. 有兼容范围、已知限制、升级与退休策略。

未满足这些条件的能力包保留为 `supported` 或 `unverified`，不能为了发布节奏改标签。

## 版本路线

| 版本 | 范围 | 发布目标 |
| --- | --- | --- |
| v3.0 | React、Vue、Angular、Node.js、Java；中英双语；三系统协议 | 团队内部可重复使用 |
| v3.1 | Svelte、Python、Go、PHP | 扩展 Web 技术栈矩阵 |
| v3.x | 真实项目证据、兼容矩阵、安装与升级协议 | 从 B 准备进入 C |
| v4 | .NET/C#、原生移动、混合 App、桌面、嵌入式、C/C++ | 扩展到非 Web 平台家族 |

版本路线是能力边界，不是发布日期承诺。每个包的真实等级以注册表和验证证据为准。
